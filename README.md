# 論文をKindleへ

Chrome標準の日本語訳 → ページ印刷PDF → Amazon.co.jp Send to Kindle をつなぐ、個人利用向けChrome拡張です。メール送信・外部翻訳API・Amazonのパスワード保存は使いません。

## インストール

1. ZIPを解凍して、フォルダーを移動しない場所に置きます。
2. Chromeのアドレス欄で `chrome://extensions` を開きます。
3. 右上の「デベロッパーモード」をオンにし、「パッケージ化されていない拡張機能を読み込む」をクリックします。
4. このフォルダー内の **extension** フォルダーを選びます。
5. 自動で開く初回設定を済ませ、拡張のアイコンを固定します。

Windows / macOSで同じファイルを利用できます。両環境での実機確認済みを意味するものではありません。

## 初回だけ必要な設定

- 英語の論文本文をChromeで開き、「日本語に翻訳」を実行。翻訳パネルのメニューから「英語を常に翻訳」を選びます。訳先は日本語に設定してください。
- https://www.amazon.co.jp/sendtokindle にログインします。
- 拡張の初回設定でチェックを入れて保存し、Amazon.co.jpへのアクセスを許可します。

Chromeの標準ページ翻訳を直接起動する公開拡張APIは利用していません。Chromeの自動翻訳を一度設定しておくことで、以後は論文ページで拡張アイコン1回の操作にできます。この設定をしない場合は、翻訳のみ手動操作が必要です。ChromeのローカルTranslator APIに置き換えていないため、普段の標準翻訳で表示された内容を印刷します。

## 日常の使い方

論文本文のWebページを開き、**「論文をKindleへ」のアイコンを1回押します**。

1. 本文・遅延読み込み画像のためページをスクロールし、元の位置に戻します。
2. 本文段落の日本語率と更新停止を確認します。完了判定は推定です。翻訳の正確さ・全文完全性を保証するものではありません。
3. Chromeの印刷エンジンでA4（設定によりA5）のPDFを作成します。ページ固有の印刷用スタイルが適用されます。
4. 新しいAmazonのSend to Kindleタブに、そのPDFのみを投入します。
5. 「ライブラリに追加する」をオンにして「送信」を押します。
6. Amazonの「ファイルは処理中です」を検出したら「Amazon受付済み」と表示します。ライブラリ反映や端末へのダウンロードはAmazon側の非同期処理で、拡張は完了確認できません。

処理中にPDFやURLを別の翻訳サービスへ送信しません。既存のChrome翻訳とAmazonへのPDFアップロードは、それぞれのサービスに通信します。

## 失敗した場合

- 未翻訳: 「論文に戻る」を押してChromeで翻訳してください。180秒までは翻訳を待ちます。参考文献は判定から除きますが、ページ構造によっては翻訳済みでも止まる場合があります。
- 翻訳/本文の読み込みが止まる: 元のタブを手前に出し、本文が読めるか確認します。購読・ログインが必要な本文は、先に正規の方法で表示してください。
- PDFビューアー: 出版社のHTML本文ページを開いてください。PDFを直接表示したタブは対象外です。
- 「別のデバッガーが接続済み」: DevToolsや同じタブを操作する自動化ツールを閉じてから再試行します。
- Amazonログイン: 送信タブでログインしてください。最大4分待機します。
- 32MB超のPDF: Chrome拡張間の大きなデータ転送を避けるため、自動投入を止めて手動送信に切り替えます。Amazon自体のWeb送信上限は200MBです。
- Amazonの画面が変わった: 自動送信せず停止します。「PDFを保存」で取り出し、Amazonへ手動送信できます。
- 送信後にエラー: 「最近送信したファイル」で確認してください。拡張は自動再送しません。同じURLの送信を再度行う場合、Amazonの状態を確認してから、処理状況の「保存PDF・履歴を消去」を押します。
- 画像・数式: ページの印刷スタイルに依存します。図中の文字はChrome標準翻訳でも翻訳されない場合があります。

## 保存・権限

- `activeTab`: 押した論文タブを対象にします。
- `debugger`: Chromeの印刷PDF作成と、翻訳状態の確認に使用します。この権限は強い権限で、Chrome上部にデバッグ中の表示が出ます。拡張コードは指定タブの確認・スクロール・印刷にだけ使用します。
- `scripting` と任意の `https://www.amazon.co.jp/*`: Amazonの送信画面のDOM操作に使用します。コードは `/sendtokindle` に限定し、購入やアカウント設定を操作しません。
- `storage`: 設定と直近の処理状況。直近1件のPDFはIndexedDBに保持され、次回PDF作成時に置き換わります。
- `downloads`: 失敗時などに手元へPDFを取り出せます。
- Amazonの認証情報・Cookieを読み出したり保存するコードはありません。
- 「保存PDF・履歴を消去」は拡張内のデータだけを消し、Amazonライブラリを変更しません。

## 検証方法

`node --test tests/core.test.mjs` でURL制限・ファイル名・PDF判定・印刷設定を検証できます。
ローカルHTTPサーバーでこのフォルダーを配信し、`tests/browser.html` の「検証を実行」で実DOMのテストができます。テストはAmazonに送信しません。

## 現在の制限

著者名の自動取得・Send to Kindleの著者欄への自動入力は未実装です。Kindleで著者がUnknownと表示される場合は、送信前にAmazon画面で著者名を編集してください。設定の「送信まで自動で行う」をオフにすると編集できます。
